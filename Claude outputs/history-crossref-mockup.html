이력·관주 팝업, 같은 언어로 다시

말씀 노트 개편 때와 같은 방식으로, 두 화면을 코드베이스 실제 색·폰트로 시뮬레이션했습니다. 아래에서 테마를 바꿔 보고, 관주 팝업은 아이콘을 눌러 열어 볼 수 있습니다.

바꾼 핵심 — 두 화면 다 BookmarkListPopover/TranslationPickerPopover가 이미 쓰는 "제목+개수 배지+원형 닫기" 헤더로 통일했습니다. 조회 이력은 지금까지 시스템 .navigationTitle을 썼는데, 스크린샷에서 보신 "닫기 버튼이 따로 떠 있고 타이틀이 흰색"인 문제 자체가 시스템 내비게이션 바 특유의 제약(이 세션에서만 벌써 4개 화면이 겪은 문제)에서 나온 것이라, 커스텀 헤더로 바꾸면 이 문제가 구조적으로 재발하지 않습니다.

관주 팝업 — 본문 위에 뜨는 작은 카드로, 절 번호 아래 마커 아이콘을 눌러 열어 봅니다. 책 이름을 강조색 세리프로 키우고 장:절은 옅게, 오른쪽엔 이동 화살표를 뒀습니다. 헤더는 조회 이력과 같은 패턴(제목+개수+닫기)이라 두 화면이 한 가족처럼 보입니다.

무엇을, 왜 바꿨나

  1. 커스텀 헤더로 통일 — 조회 이력은 지금까지 시스템 .navigationTitle + .toolbar를 썼습니다. 이 세션에서만 BibleReadingView/SearchView/WordNoteHomeView/DocumentsHomeView 네 화면이 "시스템 내비게이션 바는 앱 전체 라이트/다크 모드만 보고 타이틀 색을 정해서, 실제 배경 테마와 어긋나면 글자가 안 보인다"는 같은 문제를 겪고 각자 고쳤습니다(ThemedNavigationBarBackgroundModifier 4중 복제). BookmarkListPopover/TranslationPickerPopover는 애초에 이 문제를 겪은 적이 없는데, 진짜 시스템 내비게이션 바가 아니라 평범한 Text 헤더를 직접 그리기 때문입니다. 조회 이력도 같은 패턴으로 바꾸면 "타이틀 흰색 고정" 문제가 다시 생길 수 없는 구조가 됩니다 — 패치가 아니라 구조를 맞추는 선택입니다.
  2. 섹션 제목에 시계 아이콘 + 가로선 — "오늘/어제/그저께" 같은 시간 그룹핑이 이 화면의 핵심 정보인데, 지금까지는 평범한 볼드 텍스트 하나뿐이었습니다. 이미 빈 상태 안내(ContentUnavailableView(..., systemImage: "clock"))에 쓰고 있는 시계 아이콘을 재사용해 "이력 화면"이라는 성격을 시각적으로 한 번 더 알려주고, 오른쪽으로 뻗는 가로선으로 구분을 뚜렷하게 했습니다.
  3. 행: 구절을 강조색 세리프로, 화살표로 이동 가능함을 표시 — 지금까지는 구절/시각 둘 다 시스템 기본 서체·색이라 어느 것이 이 화면의 "주인공"인지 구분이 안 됐습니다. 성경 구절(bookChapterLabel)을 세리프 강조색으로 키우고, 시각은 오른쪽에 옅게 두고, 탭하면 이동한다는 걸 알리는 화살표를 더했습니다 — 실제로 row(for:)가 이미 Button이라 탭 가능한 게 맞으므로, 화살표는 없는 기능을 있는 것처럼 보이게 하는 게 아니라 이미 있는 기능을 드러내는 장치입니다.
  4. 관주 팝업: 헤더 신설 + 행 재설계 — 지금까지는 헤더도 없이(제목·개수·닫기 전부 없음) List 하나에 파란 시스템 버튼 텍스트가 나열될 뿐이었습니다. 조회 이력과 같은 헤더 패턴("관주" + 개수 배지 + 원형 닫기)을 그대로 가져와 두 화면이 한 가족처럼 보이게 했고, 행은 책 이름을 세리프 강조색으로 키워 "관주 대상 구절"이라는 정보가 한눈에 들어오게 했습니다.
  5. 반영/보류 — 관주 대상 구절의 실제 본문 미리보기는 넣지 않았습니다. 지금 코드(BibleVerseRef)에는 책/장/절 좌표만 있고 본문 텍스트가 없어, 넣으려면 대상 구절의 본문을 새로 조회해 와야 하는 별도 작업이 필요합니다 — 필요하시면 알려주시면 범위를 잡아 진행하겠습니다. 조회 이력 행에 노트 종류처럼 spine(책등) 색선을 넣는 것도 검토했지만, 이력 항목은 "장 단위 이동"과 "정확한 절 이동" 둘뿐이라 억지로 색을 나누면 없는 구분을 있는 것처럼 보이게 할 위험이 있어 넣지 않았습니다.

참고 — 이 목업은 실제 KMU 성곡체(.otf) 번들이나 기기 베젤(bezel) 없이, 말씀 노트 목업과 같은 이유로 상태바만 있는 단순 프레임을 썼습니다. 마음에 드시면 이 내용 그대로 Swift에 적용하겠습니다.
