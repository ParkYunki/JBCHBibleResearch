# deploy_vie1 — 베트남어 번들 성경(VIE1934) 깨진 글자 수정 (2026-10-29)

## 원인 (결론)
**원본 결함이다.** eBible `vie1934_usfm.zip`(md5 1344659729d26243d1a065bb8185f64a) 안의 USFM 자체가 깨져 있다.
- 같은 zip을 기존 변환 스크립트(`~/bibles`: usfm2db → perchap.convert5 + manual → write_db)로 컨테이너에서 다시 변환하면 Mac의 `Bible_VIE1934.sqlite`와 31,102행이 모두 같다(내용 해시 853fc2cb…, 파일 md5만 sqlite 버전 차이로 다름). 변환 과정에서 생긴 손상은 없다.
- eBible의 다른 배포 형식(`~/bibles/src/vie-vie1934.txt`)도 같은 곳이 똑같이 깨져 있다.
- 외부 대조본(biblehub / bibliaparalela / ebible.com 의 "Vietnamese (1934)")에서는 같은 절이 정상이다.

## 검증
1. `PRAGMA integrity_check` = ok(이전·이후). journal_mode = delete, 남은 -journal 파일 없음. page_count 1510 그대로.
2. 스키마 객체 2개(BibleVerses, uidx_bible_verse) SQL이 같다. 행 수 31,102 그대로.
3. uid·book_id·chapter·verse·paragraph가 다른 행 0. content가 다른 행은 2,228개이고, 전부 "이전 값에 규칙을 적용한 값"과 정확히 같다(어긋난 행 0). 규칙에 걸리는데 안 바뀐 행 0(`verify_vie1.py`).
4. 다시 돌리면 바뀌는 곳 0(멱등). 고친 뒤 `audit_vie.py`: 규칙으로 고칠 곳 0, 남은 이상 토큰 27개(모두 아래 수동 목록).
5. 원본 zip → 변환 → 후처리(`rebuild_vie1934.py`)로 만든 DB와 이 파일의 BibleVerses 31,102행이 모두 같다. 다시 변환해도 같은 결과가 나온다.

## 자동으로 고치지 않은 곳 (`manual_review.tsv`, 55건)
- **W (4절, 권장)** — 원본에서 대문자 `Ý`가 통째로 빠졌다. 외부 대조본으로만 확인되므로 기본 산출물에는 넣지 않았다. 원하면 `Tools/VIETextFix/apply_witness_W.py`를 이 파일 사본에 돌린다(이후 내용 해시 `28308b57d0f870c2029d73c29c66cf1f`).
  - 창 40:12 `nói: -nghĩa` → `nói: Ý-nghĩa` / 창 40:18 `rằng: -nghĩa` → `rằng: Ý-nghĩa`
  - 사 55:8 `phán: tưởng ta` → `phán: Ý tưởng ta` / 마 6:10 `đến; Cha được nên` → `đến; Ý Cha được nên`
- **C (2절)** — 대문자 줄이 규칙 없이 깨짐. 제안만:
  - 요 19:19 `JÊSUS NGƯùI NA-XA-RẵT, Là VUA DĂN GIU-ĐA` → `JÊSUS NGƯỜI NA-XA-RÉT, LÀ VUA DÂN GIU-ĐA` (ebible.com은 대소문자 섞어 "Jêsus Người Na-xa-rét, Là Vua Dân Giu-đa")
  - 행 17:23 `THù CHúA KHÔNG BIôT` → `THỜ CHÚA KHÔNG BIẾT` (외부 대조 못함)
- **E (1절)** — 롬 16:9 `Eâch-ta-chy`: VNI대로면 `Êch`인데 -ch 음절은 성조가 있어야 하므로 불가능한 형태. 원본 오타로 보이며 판단 필요.
- **T (48곳)** — 인코딩과 무관한 원본 오타·서식(이번 범위 밖, 보고만): `connnnn`, `ngggggggơi`, `nhờờờờờờ`, `cco tôi pưu lạc`, `Từc`, 막 16:20 `v????`, 눅 등 이름 안의 `하이픈+공백` 23곳 등.

## 연관 데이터 — `Resources/Literal_vi.sqlite` (바꾸지 않음, 보고만)
- 이 파일은 Mac 원본 그대로다(md5 f1360f413e9e1caadc74501e6e27b6e5).
- `LiteralText`(직역) 31,104행: 깨진 글자 0건. 근거가 원어+LSV라서 영향이 없다.
- `TranslationDifference`(차이 설명) 31,104행 중 **2,084행**이 깨진 VIE1934 본문을 인용한다(`Tools/LiteralGen/make_packets.py`가 `Bible_VIE1934`를 비교 입력으로 씀). 그중 1,370행은 설명 전체가 깨진 글자에 대한 말이고(예: `Chữ “Aùp-ram” trong bản 1934 là chữ hỏng (“Áp-ram”).`, `Bản 1934 có chữ “Aáy”.`), 714행은 다른 설명과 섞여 있다.
- 같은 규칙으로 글자만 바꾸면 "“Áp-ram”은 깨진 글자다(“Áp-ram”)"처럼 뜻이 틀린 문장이 된다. 그래서 고치지 않았다. 이 문장을 지울지, 다시 생성할지는 판단이 필요하다. 행마다 현재 설명과 글자만 바꾼 설명을 `literal_vi_td_review.tsv`에 넣었다.
- 창 40:12, 40:18 설명은 깨진 글자를 AI가 추측해 "thế nầy", "Nghĩa"로 읽었다. 대조본은 "thể nầy", "Ý-nghĩa"다.

## 반영 순서
1. Mac의 `JBCHBibleResearch/Resources/Bible_VIE1934.sqlite` md5가 09e7a5fe…인지 확인한다.
2. 이 폴더의 같은 경로 파일로 덮어쓴다(Xcode 대상 설정은 그대로). 앱은 번들 파일을 직접 연다(`TranslationBootstrap`, `sqliteData: nil`). 다시 빌드하면 바로 반영된다.
3. (선택) W 4절: 연결 폴더 밖 사본에서 `python3 -I Tools/VIETextFix/apply_witness_W.py 사본.sqlite`를 돌린 뒤 덮어쓴다.
4. `Tools/VIETextFix/`는 저장소 `Tools/` 아래에 두면 된다(KRVTextAudit와 같은 자리).

## 재발 방지
- 원본 USFM이 깨져 있으므로 vie1934를 다시 변환할 때는 `Tools/VIETextFix/rebuild_vie1934.py ~/bibles vie1934_usfm.zip OUT.sqlite`를 쓴다. 기존 변환을 그대로 부르고 write_db 직전에 `viefix.fix_text`를 적용한다. `~/bibles`의 기존 스크립트는 고치지 않았다.
- 변환 뒤 `audit_vie.py OUT.sqlite`로 "fixable by viefix 0"을 확인한다.
- eBible에서 새 판을 받으면 먼저 `audit_vie.py`로 원본이 고쳐졌는지 본다. 고쳐졌다면 후처리가 바꾸는 곳이 0이 된다.
- `viefix`는 정상 음절이 아닌 토큰만 건드린다. 히브리어·그리스어 문자를 바꾸지 않도록 전체 문자열 NFC 정규화는 하지 않는다.
